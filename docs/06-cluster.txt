## Notes
- Cluster created on pve1: pvecm create pve-cluster --link0 10.10.0.2
- pve2 and pve3 joined: pvecm add 10.10.0.2 --link0 <own IP>
- --link0 binds the Corosync ring explicitly to each node's internal IP instead of relying on hostname resolution
- Transport is knet (unicast); Corosync's older multicast mode does not work on GCP
- Joining replaces the node's /etc/pve with the cluster copy, so nodes must be joined before any local configuration
- Root password had to be set on pve1: pvecm add authenticates to the existing cluster as root
- Quorum is 2 of 3: one node can fail and the cluster still operates
- Web UI reachable only through an IAP tunnel; see scripts/tunnel.sh
